// ARCHITECTURE

System design and implementation details

// OVERVIEW

Washmachine is structured as a three-project solution. All business logic lives in a platform-neutral core library shared by both a standalone CLI and a WinUI 3 desktop app.

CLI-First Design

The architecture follows a CLI-first, shared-core pattern. All domain logic is implemented in the Core library first, ensuring both interfaces have equal capabilities.

Zero Coupling

GUI and CLI never reference each other. Core has no WinUI or Windows-specific dependencies. This enables testing, portability, and maintainability.

Shared flow used by both CLI and GUI:

Separation of Concerns

UiDataFactory extracts a headless snapshot from the visual tree. This UIData object is then passed to Core services, which have zero knowledge of WinUI controls.

// DEPENDENCY INJECTION

Core services use constructor injection for testability:

public class CompilerService
{
    private readonly IAppLogger _logger;
    private readonly YamlCodeSnippetCatalogService _catalog;
    private readonly Bin2ShellRunner _bin2shell;

    public CompilerService(
        IAppLogger logger,
        YamlCodeSnippetCatalogService catalog,
        Bin2ShellRunner bin2shell)
    {
        _logger = logger;
        _catalog = catalog;
        _bin2shell = bin2shell;
    }

    // ...
}

CLI: Manual Wiring

var logger = new ConsoleLogger();
var catalog = new YamlCodeSnippetCatalogService();
var bin2shell = new Bin2ShellRunner(logger);
var compiler = new CompilerService(logger, catalog, bin2shell);

GUI: Injected in Controller

// Services initialized in MainWindow constructor
var logger = new RichTextBoxLogger(LogRichEditBox);
var catalog = new YamlCodeSnippetCatalogService();
// ...
coordinator = new MainFormCoordinator(..., compiler);

// KEY DESIGN DECISIONS

Single YAML Catalog

All templates and snippets in one file (vx_api_snippets.yaml). No recompile needed to add techniques.

✓ Instant extensibility

Headless Core

Business logic has zero UI dependencies. Services operate on UIData snapshots, not controls.

✓ Testable & portable

Auto-Discovery

Compiler detection scans PATH, VS install paths, and VCToolsInstallDir. Bin2Shell options read from live help output.

✓ Zero manual configuration

Session Logging

Every compilation saves source + build log to timestamped directory with UUID.

✓ Full audit trail

Subprocess Isolation

Compilers and Bin2Shell run as separate processes. Failures are captured, not fatal.

✓ Robust error handling

Deduplication

Snippet includes and implementations are deduplicated during assembly.

✓ Clean generated code
