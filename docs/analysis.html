📌 What It Is

Washmachine is a modular, template-driven shellcode evasion framework built for red teamers and security researchers. From raw shellcode bytes to a fully backdoored PE, the entire offensive pipeline lives in one tool available as both a Metasploit-style CLI and a WinUI 3 desktop app.

The standout feature is the YAML-based playbook system. Every C++ template and code snippet is defined in Assets/default.yaml — swappable without touching the codebase or recompiling. When a technique gets flagged by a new signature, update the playbook.

🏗️ Architecture

✓ Good design decisions
The Core/CLI/GUI separation is clean. Both UIs share identical service instances. The YAML catalog decouples technique management from code — a new snippet is one YAML block, no recompilation. The REPL (Metasploit-style) + inline (PowerShell-style) dual CLI modes are fully working and tested.

🔌 Stubs — Defined but Not Wired

These exist in models/enums/service code but are blocked with "not implemented" errors in the CLI:

💊 PayloadEncryption.Xor / Xor2 / Rc4 — model only, not a backdoor concern

These enum values exist in PeBackdoorModels.cs and were surfaced in the GUI encryption combo. However, payload encoding and encryption is handled at the Encode stage (encode → bin2shell). The backdoor command injects the already-prepared flat .bin as-is. The GUI encryption combo has been removed and replaced with an informational note. These enum values may remain for potential future use in other contexts.

🎯 CarrierInvoke.EntryFunctionBackdoor

Defined in the enum. Would patch the first JMP/CALL inside the entry function body rather than the entry point header itself — stealthier against heuristics that inspect AddressOfEntryPoint bytes specifically.

📦 CarrierInvoke.DllMain / DllExport

Defined for DLL backdooring. PeBackdoorOptions already has a DllExportName field. The CLI hard-rejects DLLs — the model and intent exist but the implementation path was never written.

📍 PayloadLocation.RdataSection / TextSection

Enum defined. BackdoorAsync always places payload via the injection method — the location selector is never surfaced in the CLI argument parser.

🚫 -NoPreserveEntry

Flag is parsed from the CLI args but immediately returns exit 1. The carrier always resumes the original entry point regardless.

📦 Packing Stage (PackingPage.xaml)

The GUI navigation has a Packing page. The pipeline flowchart shows it between backdoor and finalize. The XAML file exists but the page is empty — no packing logic has been implemented anywhere in Core.

Entry-function carrier (EntryFunctionBackdoor) Stub completion

Instead of redirecting AddressOfEntryPoint itself, patch the first JMP/CALL instruction inside the entry function body. This is stealthier: many AV heuristics inspect the first bytes at the recorded entry point address specifically. Already defined as CarrierInvoke.EntryFunctionBackdoor.

High impactMedium effortPeBackdoorService.cs
04
Entropy analysis in analyze New feature

Per-section Shannon entropy is a primary AV/EDR signal. Currently analyze shows section sizes and permissions but not entropy. A high-entropy .text or .data section is often why a loader gets flagged before it even executes. This is a critical planning tool — "my .rsrc entropy is 7.98" — and requires zero dependencies.

analyze -Pe target.exe
Section  RVA        Size     Entropy  Executable
.text    0x1000     0x8200   7.98 ⚠ HIGH  ✓
.rdata   0x9000     0x1800   4.21      ✗
.data    0xb000     0x0400   2.87      ✗
High impactLow effortPeAnalyzerService.cs · RunAnalyzeAsync
05
Packing stage New feature

PackingPage.xaml exists as a placeholder in the GUI. The pipeline flowchart shows Packing between Backdoor and Finalize. Adding UPX packing (auto-provisioned the same way Bin2Shell is) would complete the flowchart. Alternatively support a user-provided packer command via a script hook.

🟡 Medium Priority Features

06
CLI recipe import / export CLI gap

The GUI already has ExportRecipeAsync/ImportRecipeAsync on CompilePage. The CLI has no equivalent. A recipe is a JSON snapshot of the template + snippet selections — essential for repeatable builds.

encode -ExportRecipe recipe.json
encode -ImportRecipe recipe.json -Shellcode payload.bin
Medium impactLow effortProgram.EncodeInteraction.cs
07
PE checksum recalculation after backdoor OPSEC

After backdooring, the Checksum field in the Optional Header is stale. Many integrity checkers and loaders verify it. PeBackdoorService already locates ChecksumFieldFileOffset and can write to it — it just needs the algorithm (implementable in pure C#, equivalent to MapFileAndCheckSum). The field write code path already exists.

Medium impactLow effortPeBackdoorService.cs
08
Timestamp stomping OPSEC

Clone the TimeDateStamp from the Optional Header of a legitimate donor binary (or zero it). Easy 10-line addition to PeBackdoorService, big OPSEC improvement. Add a -StompTimestamp <donor.exe> flag or make it automatic with -CloneFrom.

Medium impactLow effortPeBackdoorService.cs
09
RICH header wiping OPSEC

The RICH header (between the DOS stub and PE header) reveals which compiler version and linker produced the original binary. Wiping it (XOR every DWORD with the embedded key, then zero the block) removes a static fingerprint that threat intel platforms use to cluster malware families. The backdoor service already parses the PE header vicinity.

Medium impactLow effortPeBackdoorService.cs
10
IAT flagging in analyze New feature

Color-code suspicious imports (VirtualAlloc, WriteProcessMemory, CreateRemoteThread, NtQueueApcThread, OpenProcess…) in the analyze output. This helps the user understand why a loader is flagged statically before they test it. The import list is already collected in PeInfo.Imports.

Medium impactLow effortPeAnalyzerService.cs · RunAnalyzeAsync
